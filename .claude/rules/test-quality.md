# Test Quality Rules

**Version**: 1.0.0

> テスト改ざん防止ルール - Claude Code がテスト失敗時にテスト自体を改ざんすることを防ぎます。

---

## 🔴 禁止事項

以下の操作は**絶対に禁止**されます：

### 1. テストの無効化

- ❌ テスト関数に `#[ignore]` 属性を追加
- ❌ テスト関数をコメントアウトまたは削除
- ❌ テストモジュール全体を無効化

```rust
// ❌ 禁止
#[ignore]
#[tokio::test]
async fn test_something() { ... }

// ❌ 禁止
// #[tokio::test]
// async fn test_something() { ... }
```

### 2. アサーションの削除・緩和

- ❌ `assert!`, `assert_eq!`, `assert_ne!` の削除
- ❌ アサーション条件を `true` に変更
- ❌ エラーパターンマッチの削除

```rust
// ❌ 禁止
// assert_eq!(result, expected);

// ❌ 禁止
assert!(true);  // 常に成功するアサーション

// ❌ 禁止
if let Err(e) = result {
    // エラーを無視
}
```

### 3. テスト対象コードの改ざん

- ❌ テストを通すためだけの一時的な変更
- ❌ 本番ロジックをハードコード値に置換
- ❌ エラーを `panic!` で握りつぶす

```rust
// ❌ 禁止: テストを通すためのハードコード
pub fn calculate(x: i32) -> i32 {
    // 42  // 本来のロジックを削除
    x * 2  // 本来のロジック
}
```

### 4. Lint/Clippy設定の緩和

- ❌ `#[allow(...)]` 属性の乱用
- ❌ `clippy.toml` での警告レベル変更
- ❌ テストが通るためだけの警告抑制

```rust
// ❌ 禁止: 警告を不適切に抑制
#[allow(dead_code)]
fn unused_function() { ... }
```

## ✅ 正しい対処法

テストが失敗した場合、以下の手順で対処してください：

### 1. 失敗の原因を特定

```bash
cargo test -- --nocapture
```

### 2. 本当のバグか判断

- **実装のバグ**: 実装コードを修正
- **テストのバグ**: テストコードを修正（ロジックが正しい場合のみ）
- **環境の問題**: 依存関係や設定を確認

### 3. 実装を修正

```rust
// ✅ 正しい: 実装を修正してテストにパス
pub fn calculate(x: i32) -> i32 {
    x * 2 + 1  // バグを修正
}
```

### 4. 新しいテストを追加（必要な場合）

バグの回帰を防ぐためにテストを追加：

```rust
#[tokio::test]
async fn test_edge_case() {
    // エッジケースのテストを追加
}
```

---

## 🚨 違反時の対処

このルールに違反した操作が検出された場合：

1. 操作を元に戻す（`git checkout`）
2. 正しい対処法で問題を解決
3. すべてのテストがパスすることを確認

```bash
git checkout src/ tests/
cargo test
```

---

## 📋 チェックリスト

PR や変更を提出する前に：

- [ ] すべてのテストがパスしている (`cargo test`)
- [ ] テストを無効化していない
- [ ] アサーションを削除していない
- [ ] ハードコードで対応していない
- [ ] Clippy の警告がない (`cargo clippy`)
